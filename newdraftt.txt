
Project Draft: Govt Scheme Q&A Web Application
=============================================

1) Project Summary
- Name: govt-scheme-qna
- Purpose: Provide an AI-powered Q&A platform for government scheme documents allowing admins to upload documents and citizens to ask questions (supports Marathi and English). The system uses RAG-style responses via LLMs and semantic search over document embeddings.

2) High-level Features
- Admin panel for uploading/managing scheme documents.
- Citizen-facing chat interface (text/voice) for Q&A on schemes.
- Document processing pipeline: PDF extraction, OCR (Tesseract), text preprocessing, chunking, embeddings, and semantic search.
- AI integration: Google Gemini / OpenAI / Azure adapters for RAG.
- Analytics: Simple usage analytics auto-updated hourly.

3) Tech Stack
- Frontend: React (create-react-app) with React Router, Recharts for charts.
- Backend: Node.js + Express.js
- Database: MongoDB (via Mongoose), with vector-search capabilities represented in code (embedding storage / DocumentChunk model).
- Storage: Cloudinary (for uploaded files) and local uploads folder references.
- AI/Embedding: Google Gemini, OpenAI, Azure SDKs (multiple service adapters present).
- Other: PDF parsing (`pdf-parse`), OCR (`tesseract.js`), natural language utilities (`natural`).

4) Key Scripts (from package.json)
- Root: `npm run dev` (starts server + client concurrently), `npm run install-all` to install dependencies across root/client/server, `npm run build` builds client.
- Client: `npm start` / `npm run build` (react-scripts)
- Server: `npm start` (node server.js), `npm run dev` (nodemon server.js)

5) Primary Files and Directories (quick guide)
- [client/](client): React app. Key files: `src/index.js`, `src/App.js`, components under `components/`, API layer at `src/services/api.js`.
- [server/](server): Express backend.
  - `server.js` - main entrypoint (DB connect, Google API init, route registration, health checks, analytics timer).
  - `config/` - `database.js` (DB connection), `googleApis.js` (Google API initialization).
  - `routes/` - API routes: `auth`, `scheme`, `chat`, `upload`, `simpleAnalytics`.
  - `controllers/` - route handlers: `auth.js`, `chat.js`, `scheme.js`, `upload.js`, `simpleAnalytics.js`.
  - `services/` - business logic and integrations (AI adapters, embedding services, Cloud Storage, PDF extraction, semantic search, translation, text preprocessing).
  - `models/` - Mongoose schemas: `User`, `Scheme`, `DocumentChunk`, `AnalyticsSummary`, etc.
  - `middleware/` - auth, upload handling, analytics middleware, validation.

6) Environment & Configuration (required)
- Copy `server/env.example` -> `server/.env` and populate:
  - `MONGO_URI` or similar DB connection string
  - API keys for Google Gemini / OpenAI / Azure (depending on which integration is used)
  - `JWT_SECRET` for authentication
  - `CLOUDINARY_URL` or relevant cloud storage credentials
  - `CORS_ORIGIN` to allow frontend origin in dev/prod
- Confirm any additional env vars referenced in `config/googleApis.js`, `services/*`, and `server/.env`.

7) How to Run Locally (recommended steps)
1. Install deps for root, client, server:

   npm run install-all

2. Configure environment:

   copy server/env.example to server/.env and set values (Mongo URI, API keys, JWT secret)

3. (Optional) Seed admin user:

   node server/seed.js

4. Start dev servers:

   npm run dev

   - This runs the server (port 5000 default) and the React client (port 3000). Client proxies API requests to `http://localhost:5000` per `client/package.json` proxy setting.

5. Health checks to confirm services:

   - GET /api/health
   - GET /api/health/database

2. PRODUCT PURPOSE
--------------------------------------------------------------------------------
A bilingual (English / Marathi-oriented) citizen-facing assistant plus an admin console for
government scheme metadata and PDF documents. Citizens browse schemes, open scheme detail pages,
and chat with an AI that answers from retrieved document text (RAG). Admins authenticate,
create/update/delete schemes, upload PDFs to cloud storage, and view lightweight analytics.


3. TECHNOLOGY STACK
--------------------------------------------------------------------------------
Frontend (client/)
  • React 18, React Router 6, Axios, react-hot-toast, Framer Motion, Recharts (admin charts),
    Headless UI / Heroicons.
  • Development proxy: package.json sets proxy to http://localhost:5000 for same-origin API calls
    during CRA dev (production uses REACT_APP_API_URL).

Backend (server/)
  • Node.js, Express 4, Mongoose 7 (MongoDB).
  • Auth: JWT (Bearer), bcrypt password hashing.
  • File uploads: Multer with memory storage; PDFs stored on Cloudinary (raw uploads).
  • PDF/text: pdf-parse, mammoth (DOCX mentioned in legacy extraction paths), optional OCR-related
    deps in package.json for robust extraction services.

AI / NLP pipeline
  • Google Gemini (@google/generative-ai): chat model gemini-2.5-flash for answer generation;
    embedding models text-embedding-004 or embedding-001 as fallback.
  • Azure OpenAI (via @azure/openai): preferred path for embeddings (see azureEmbeddingService.js).
  • Hybrid embedding strategy in aiService.js: try Azure first → Gemini embeddings → last-resort
    simulated random vectors (development fallback only; poor retrieval quality).
  • Azure Translator (REST): query translation to English for search; answer translation from English
    to user language (e.g. Marathi).

Infrastructure / ops
  • Root vercel.json: static build for client only (Heroku-style postbuild noted in root package.json).
  • Server timeouts extended to 120s for AI workloads.

Request flow (scheme-specific Q&A):
  User message (+ optional schemeId, language)
    → ChatController loads Scheme metadata
    → SemanticSearchService: translate query to English → embed query → cosine similarity vs
       DocumentChunk.embedding for that scheme (filters: processingStatus completed,
       metadata.qualityScore ≥ 0.5)
    → Top chunks merged with scheme title/description as context
    → AIService: Gemini generates English answer → refined (markdown stripped, length limits) →
       translated to UI language if not English
    → JSON response with answer, confidence, PDF chunk sources.


5. DATABASE MODELS (server/models/)
--------------------------------------------------------------------------------
User
  • email (unique), bcrypt-hashed password, name, role enum admin | super_admin, department,
    isActive, lastLogin, password reset fields.

Scheme
  • title, description, category (fixed enum: Education, Healthcare, …, Other),
    pdfFile { url, publicId, filename, path }, isActive, createdBy/updatedBy/deletedAt/deletedBy,
    timestamps. Text indexes on title/description; soft-delete hooks cascade DocumentChunk deletion
    when deactivating.

DocumentChunk
  • schemeId, chunkId, content, embedding [Number], metadata (page, section, chunkIndex, language,
    contentType, keywords, qualityScore, …), processingStatus, usageStats (retrieval counts).
  • Powers semantic search; embeddings must match query vector dimensions (service logs warn on
    768 vs 1536 mismatch).

AnalyticsSummary
  • Four document types: page_view, unique_session, search_query, chat_interaction — counts and
    previousCount for trend % on admin dashboard. Hourly job in server.js copies current counts to
    previousCount for trend baseline.

7. DOCUMENT & EMBEDDING PIPELINE (critical paths)
--------------------------------------------------------------------------------
A) Primary path (recommended — used when creating/updating a scheme with PDF):
   • Scheme controller uploads PDF buffer to Cloudinary (folder govt-schemes, raw PDF).
   • Saves Scheme with pdfFile.url pointing to secure_url.
   • Asynchronously calls embeddingService.processPDFForScheme(schemeId, cloudinaryUrl, options):
        pdfExtractionService downloads/parses PDF → textPreprocessingService chunks text →
        aiService.generateEmbeddings → DocumentChunk documents inserted in MongoDB.

B) Secondary path (upload controller services/document.js processDocument):
   • Extracts text and counts chunks but does NOT call embeddingService or write DocumentChunk rows
     in the reviewed code path. Admin “extra document” upload may not populate vectors unless the
     product workflow relies solely on scheme-level PDF processing.

Operational implication: RAG quality depends on successful processPDFForScheme runs and valid API keys
for embedding providers.
